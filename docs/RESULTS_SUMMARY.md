## 4. How to read this (limitations)

- Small sample (7 apps, 1 synthetic); intervals are wide; differences may be noise.
- Risk coverage is a fixed keyword rubric, not an LLM judge; it can miss paraphrases.
- Invented-resource rate counts guardrail violations in the FIRST draft, before retries.
  The baseline has no mapping table, so Google Cloud products outside `mapping.yaml` count against it by design.
- Terraform pass rate measures the templated generator, not the LLM.
- A run that ends `could_not_verify` produces no plan and is scored as zero precision and recall. The guardrail only accepts AWS services present in the detector inventory, so a repo that really uses services outside `mapping.yaml` (for example EC2) cannot get a verified plan; see the per-app rows and `eval/results/agent/<app>.json` rejections.
- The guardrail's retry loop did not trigger on any app that passed; those plans were clean on the first draft, so its recovery value is not demonstrated by these runs.
- Scoring was adjusted once, after the first baseline run, because two artifacts showed up: lines that negate usage ('RDS is absent') are not counted as usage claims, and bare IAM is neutral in precision, recall and mapping. The same scorer applies to both modes.
- Known scorer limit: 'CloudWatch Events' (an alias of EventBridge) is read as CloudWatch.
- The service precision/recall rows score the plan text, so they measure what the model wrote, not what the detector found.
- Free-tier Gemini, one model; nothing was deployed to Google Cloud.
